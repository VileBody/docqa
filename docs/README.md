## Оценить решение без запуска — около 15 минут

| Порядок | Прочитать | Зачем |
|---|---|---|
| 1 · 7 минут | **[Технический разбор](FINAL_REPORT.md)**, разделы 1–7 | ТЗ, собственные решения, достоверность, компромиссы и неподтверждённые пункты |
| 2 · 3 минуты | **[Контрастные примеры](API_EXAMPLES.md)**, первые четыре | Увидеть разницу между найденным фактом, ответом на вопрос и отказом |
| 3 · 5 минут | **[Эксперименты](EXPERIMENTS.md)**, контекст / агенты / reader | Проверить интересующее решение по парной таблице и ограничениям |

Время — ориентир чтения, не измеренная метрика. Для проверки методики отдельно: [паспорта наборов и оценивание](RESULTS_GUIDE.md), [ContractNLI/IIRC](PUBLIC_BENCHMARKS.md), [полнота требований](REQUIREMENTS_TRACEABILITY.md). Машинные свидетельства — в [указателе](submission/evidence/README.md).

## Если тема новая

[Вводная и карта кода](PROJECT_GUIDE.md) объясняют RAG, компоненты и путь запроса. Этот маршрут необязателен для технического разбора.

| Обозначение | Значение |
|---|---|
| P0 / P1 | Версии инструкции reader; P1 включает шесть демонстраций |
| Flow / raw / pack | Один проход поиска / исходный вопрос / переданные reader фрагменты |
| Dev / reserved | Набор разработки / авторский отложенный набор |
| H01–H12 | Идентификаторы исторических HTTP-проверок |
| Submission v1 / v2 | Версии поставки; v2 добавляет ограниченные транспортные retries |
| Sosana / Luna, Sol, Astra | Варианты провайдера; upstream не подтверждён |

`assets/` хранит схемы и данные графиков; `submission/` — manifests и свидетельства. Стабильные имена файлов сохранены для существующих ссылок. Главная техническая история одна — `FINAL_REPORT`; остальные страницы раскрывают отдельную роль.
