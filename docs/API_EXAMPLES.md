# Ответы сервиса на конкретных примерах

[Документация](README.md) · [Почему выбрана эта конфигурация](EXPERIMENTS.md) · [Запуск API](RUNNING.md)

Ниже **9 реальных ответов Sol/P1 v1** на синтетических документах: вопросы, ответы и цитаты сохранены дословно. Они входят в историческую HTTP-проверку, а не получены заново для оформления README. Три real-TXT случая публично не раскрываются.

В v1 была одна попытка вызова; текущая v2 допускает до трёх при временных сбоях. Это не повод переименовывать старые ответы в новый live-прогон. [JSON с происхождением и описанием удаления служебных полей](submission/evidence/SYNTHETIC_HTTP_OUTPUTS.json).

## Что демонстрируют примеры

| Ситуация | Ожидаемое поведение |
|---|---|
| Точный факт, запрет или расчёт | Ответ с исходной цитатой |
| Нет нужной суммы или запрошенного события | Отказ; сведения по соседней теме не подставляются |
| Перефразировка или явная эквивалентность | Ответ сохраняется, если условия действительно те же |
| Новый клиент | Предыдущий диалог не влияет на вопрос |

## Другой момент начала срока — отказ

Идентификатор проверки: `H03`. [Исходный TXT](../examples/acceptance/alpha.txt).

**Вопрос:** Сколько рабочих дней ждать стандартную отправку после подачи заявки?

**Ответ:**

> Недостаточно сведений в источниках.

`status=not_found` · `found=false`

В документе описана доставка с получения заявки. Вопрос про отправку с подачи: это другие действие и начальное событие. Подлинная цитата о доставке не установила бы запрошенный срок.

Цитат в ответе нет (`citations=[]`). Это результат проверки данного вопроса, а не утверждение, что весь документ пуст.

<details>
<summary>Посмотреть сохранённый JSON ответа</summary>

```json
{
  "answer": "Недостаточно сведений в источниках.",
  "citations": [],
  "found": false,
  "status": "not_found",
  "support_check": "abstained"
}
```

</details>
